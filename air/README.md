# `air` — набор «Авиаперевозки»

Выпуск `air-data-v1`: данные авиаперевозок на основе демонстрационной базы Postgres Pro «Авиаперевозки» 2.0
(выгрузка `demo-20250901-2y`, MIT © 2025 Postgres Professional): 9 таблиц, ≈ 74 млн строк — аэропорты, самолёты и
места, маршруты, рейсы, брони, билеты, перелёты, посадочные талоны; сезонность по регионам и праздникам. Что
изменено против выгрузки и какие поля в таблицах — `SOURCE.md`.

## Проверка скачанного выпуска

Из корня репозитория — та же команда, что у всех наборов:

```bash
python3 -X utf8 -I tools/check_data.py ПАПКА_ВЫПУСКА        # Linux, macOS
py -3 -X utf8 -I tools\check_data.py ПАПКА_ВЫПУСКА          # Windows
```

Ожидания — `air/expected/air-data-v1-full.json`: строки, `sha256_tsv` и `sha256` каждой таблицы и sha256 `LICENSE`
из `manifest.json` выпуска (агрегатов пока нет). Прежняя проверка — `python air/check_air_data.py ПАПКА` — тоже
работает.

## Сборка

Сейчас — скриптами на Python, вручную:

| файл | что |
|---|---|
| `build_air_data.py` | выпуск из выгрузки демобазы: время в секундах Unix, отбор броней целиком (сезонность), справочник аэропортов без нескольких аэропортов источника (список — в `build_air_data.py`), упорядочение, gzip без отметки времени |
| `source_md.py` | `SOURCE.md` выпуска — из `manifest.json` |
| `check_air_data.py` | прежняя проверка собранного выпуска |
| `SOURCE.md`, `LICENSE` | описание набора и лицензия данных |

Сборка переезжает на общий шаблон наборов (см. `README.md` в корне): генератор на Java в `air/src/` — импорт из
дампа демобазы, профили `small` (≈ 1 %) и `full`, паспорт `dataset.properties` с дампом по ссылке и его sha256,
схема `air/schema/` и ожидания `air/expected/` из `freeze`; тогда выпуск собирает CI по тегу `air-data-v*`. До
переезда паспорт говорит `build=python`, и CI такой тег отклоняет.
