## Что изменено

### Файлы апстрима

| Файл | Изменение |
|---|---|
| `route.sql` | 1) В `build_routes()` после случайного графа (по два направления от каждого аэропорта) и до досборки связности вызывается `hh_permanent_directions()`, но только при `gen.hh_hubs = on`. Без этого параметра генератор работает как у авторов. 2) В `add_route()` номер маршрута раньше собирался как `lpad(rno::text,4,'0')`, и номера больше 9999 обрезались до четырёх цифр; повтор номера в том же периоде нарушает ограничение EXCLUDE таблицы `bookings.routes`. Теперь до 9999 формат прежний (`PG0001`), дальше номер пятизначный (`PG10000`). При 304 аэропортах за 25 перестроений набирается около 13 300 различных пар аэропортов. |
| `engine.sql` | В `do_init()` при расчёте `gen.airport_to_prob` пары аэропортов ближе `gen.hh_min_km` км исключаются. Из этой таблицы выбираются и назначения бронирований (`airport_to()`), и направления случайного графа (`build_routes()`), так что ни поездок, ни прямых маршрутов короче этого расстояния нет. Признак `domestic` считается по оставшимся парам: у аэропорта, у которого не осталось внутренних назначений, все назначения считаются как у страны с одним городом. Без параметра (0) результат прежний. |
| `booking.sql` | В `get_path()` условие «пересадка не дольше `gen.max_transfer`» записано в виде, который может использовать индекс: `f.scheduled_departure < coalesce(p.last_arrival_time + …, 'infinity')`. Добавлено следующее из него ограничение `lower(r.validity) < …` для индекса по `routes`. Результат поиска тот же (проверено на 608 парах аэропортов, совпали все), а на сети из 304 аэропортов сам поиск идёт примерно в 3,5 раза быстрее, генерация в целом — примерно вдвое. |
| `names.sql` | В `calc_names_cume_dist()` при `gen.hh_names_tiebreak = on` у оконной суммы есть второй ключ сортировки — само имя (`COLLATE "C"`). Без него имена с одинаковым `qty` получают общее значение `cume_dist`, и `get_passenger_name()` из каждой такой группы всегда выбирает одно и то же имя. Для справочников, где частоты — небольшие целые числа, это сводит выбор к нескольким именам на страну. При том же параметре имена соединяются ещё и по группе (`grp`): у авторов строки сопоставляются только по стране и имени, и имя, которое есть в двух группах, получает значение `cume_dist` одной из них. Без параметра формула прежняя. |
| `airports_data.dat` | Убраны 40 аэропортов стран, регионов и городов, которых нет в наборе «Мир» (`wld-data-v1`): CMJ CYI EUN GIB GIL GNI GZA HCN HSZ HUN IXJ IXL KDU KHC KHH KNH KYD LZN MFG MFK MPN MZG PIF PRN PSY RAZ RMQ SIP SMW SUI SXR TNN TPE TSA TTT TXG UKS VIL WOT XJM. В сеть они не входили, рейсов у них не было. Ещё убраны восемь аэропортов вне сети (DAN DNV GFR LKG RGA RVE RVT SON) — по правилам публичных текстов проекта; остальные 5 453 строки — как у авторов. |
| `firstnames.dat`, `lastnames.dat` | Убраны пять строк — два имени (CL, GB) и три фамилии (CL, DE, GB) — по тем же правилам; остальное — как у авторов. |
| `NOTICE.md` | Этот файл (новый). |

### Дополнения (`hh/`)

| Файл | Назначение |
|---|---|
| `hh/network.tsv` | Маршрутная сеть: 304 аэропорта в 87 странах (`code, country2, market, hub, traffic, why`), из них 45 хабов. В сеть входят все 73 аэропорта исходной сети, их `traffic` не меняется. Сумма `traffic` — 6 268,3 (было 2 270,2). |
| `hh/markets.tsv` | Рынки: `EUR, NAM, LAM, FEA, ASI, PAC, AFR` (`code, name_en, name_ru`). |
| `hh/firstnames_extra.dat`, `hh/lastnames_extra.dat` | Имена и фамилии для 70 стран, которых нет в справочниках авторов. Формат тот же, что у `firstnames.dat` / `lastnames.dat` (`country, grp, name, qty, cume_dist`, `cume_dist` = `\N`). У AZ, BG, BY, GR, IS, LT, LV, PL имена и фамилии разделены на группы `f`/`m` (форма фамилии зависит от пола), у остальных стран `grp` = `-`. Частоты собраны по открытым данным Wikidata (CC0). Взяты только имена и фамилии, которые встречаются хотя бы у двух людей; где таких мало, добавлены имена соседних по языку стран. |
| `hh/network.sql` | Таблицы `gen.hh_markets` и `gen.hh_network`. `gen.airports_data.traffic` получает значения из `network.tsv`, у аэропортов вне сети ставится NULL. У аэропортов сети устаревшие имена часовых поясов заменяются каноническими (`America/Buenos_Aires` → `America/Argentina/Buenos_Aires`, `America/Cordoba` → `America/Argentina/Cordoba`, `Asia/Saigon` → `Asia/Ho_Chi_Minh`), потому что серверы, у которых в системной базе tz нет устаревших имён, их не распознают. Проверки: все коды есть в справочнике и страны совпадают, значения исходных 73 аэропортов совпадают, у каждого рынка есть хаб, все часовые пояса сети сервер знает. |
| `hh/names.sql` | Дописывает строки `*_extra.dat` к `gen.firstnames` / `gen.lastnames` и пересчитывает `cume_dist` процедурой авторов. Проверяет, что у каждой страны сети есть имена, а для каждой группы имён — фамилии (иначе `get_passenger_name()` зацикливается). |
| `hh/routes.sql` | `hh_permanent_directions()` — постоянные направления (туда и обратно, через `add_direction()`): (а) два крупнейших по `traffic` хаба каждого рынка соединяются с двумя крупнейшими хабами каждого другого рынка («топ-2 ↔ топ-2»), если расстояние не больше дальности самого дальнего самолёта `in_use`; у остальных хабов межрыночных постоянных направлений нет; (б) при `gen.hh_spokes = on` каждый аэропорт, который не хаб, соединяется с ближайшим хабом своего рынка не ближе `gen.hh_min_km` (кроме аэропортов того же города). Самолёт и частоту рейсов, как и раньше, выбирают `add_route()` и `suitable_aircraft()`. |
| `hh/install.sql` | Ставит параметры `gen.hh_hubs`, `gen.hh_spokes`, `gen.hh_names_tiebreak` (все `on`) и `gen.hh_min_km = 150`, затем выполняет три файла выше. Запускается после `install.sql`, до `CALL generate()`, потому что сеть и имена нужны уже на этапе INIT. |
| `hh/run.sh` | Подкоманды `install`, `start`, `continue`, `status`, `export`, `check`, `abort`. Подключение задаётся переменными `PG*`. `start` держит сеанс запуска открытым в фоне до конца генерации: процессы генерации подключены к нему через dblink, и сообщение NOTICE в уже закрытое соединение завершает процесс. При `jobs > 1` сначала идёт разгон одним процессом до начала продаж, иначе первые бронирования проходят раньше, чем становятся видны рейсы. При ошибке в `gen.log` генерация прерывается. `continue` возвращает в очередь события, которые обрабатывались в момент остановки (после `abort` или штатной остановки сервера). `export`: `export.sh` → gzip → части по 1900 МБ → `SHA256SUMS`, `MANIFEST.txt`. |
| `hh/LAPTOP.md` | Порядок команд для полного прогона в Docker Desktop под Windows. |
| `hh/source_md.py` | `SOURCE.md` выпуска снимка (`air-source-YYYYMMDD`) по папке выгрузки: файлы и суммы, строки, параметры `gen.*` (без адреса подключения), версия сервера и образ. |
| `hh/IMPORTER.md` | Чем выгрузка форка отличается от выгрузки авторов (для разборщика дампа). |
| `.gitattributes` | Перевод строки LF для `*.sh`, `*.sql`, `*.md`, `*.py`; `*.dat`, `*.tsv` и `*.txt` не преобразуются (на Windows CR ломает bash и `\copy`, а файлы авторов остаются байт в байт). |

Схема `bookings` (состав таблиц и колонок), формат выгрузки (`export.sh`) и все
прочие параметры `gen.*` не изменены. Объекты дополнений лежат в схемах `gen` и
`public` и в выгрузку не попадают.

## Как пользоваться

```sh
cd <каталог генератора>
hh/run.sh install                      # install.sql + hh/install.sql
hh/run.sh start 2025-09-01 2027-09-01 16
hh/run.sh status                       # повторять по мере надобности
hh/run.sh export /path/to/out          # после окончания генерации
```

`hh/run.sh install mode=base` — только авторская установка: исходная сеть, без дополнений.
